# Native screen fade, overlay and script commands

Thirteen complete PS2 bodies are reconstructed in `src/screen_fade.c`, using eleven reviewed Unity counterparts and two descriptive native aliases. This covers fade state clearing, RGB/RGBA setters, both directions and retained-color variants, checking/updating, the DMA chain builder, the complete overlay packet and script commands 15/16. Work proceeds in the existing Ghidra project, with rolling captures overwritten in place.

The original PS2 behavior supplies the implementation. Duration tests use the full 64-bit argument before storing unsigned 16-bit counters. Colored zero-duration FadeIn clears RGB; the retained-color variant preserves it. Updates wrap the halfword counter before division and clear direction bits only at the native completion condition. Both direction flags and dirty high argument lanes are retained in the generated cases.

Unity provides names and structural leads but changes behavior. The HD retained-color variants do not perform the same initial alpha stores, FadeCheck adds a model-loading gate, Update has additional final-frame handling, and Draw clamps alpha. Native alpha above 128 remains unchecked: its negative shifted word sign extends into the upper RGBA lanes. The native RGBA setter is not the HD ColorGet output getter.

The native overlay builds the full 176-byte packet for the shared context index, then calls the actual work allocator, chain initializer, packet append and initialized ordering callback. Independent checks cover packet headers, RGBA lanes, fixed rectangle vertices and linked-chain state. Physical GS rendering remains outside these checks.

Script commands 15/16 use actual typed parameter accessors. With timer zero, mode zero selects black and mode one selects white; invalid modes complete without creating a fade. A valid first call starts the fade and yields. Any nonzero timer completes the command on the next interpreter entry; the command does not wait for the fade duration. Connected cases execute the original VM, one actual fade update and overlay drawing before interpreter completion.

All 2,144 comparisons pass, including 48 zero-total traps, 63 unchecked-alpha cases, 297 actual ordering submissions and 672 real VM indirect calls. The affected C builds with MSVC `/W4 /WX`; thirteen interfaces are saved and checked after reopening, and thirteen selected current exports are merged. The progress index now records 1,137/8,975 compiled and compared routines (12.669%) and 619,226 aggregate cases. Of this batch, 2,048 cases belong to newly added bodies; the 96 existing-interpreter cases are not added again to the aggregate. No new full-suite run is claimed.

The current comparison suite covers 1,672 recognized body bytes and all 357 main instruction addresses in 2,144 generated cases, including 96 connected interpreter programs and 64 fade/update/draw sequences. It compares declared RAM, defined returns, Status, primitive counts, preserved registers and ordered VM/drawing traces, plus independent state/packet/linkage expectations. Captures execute original instructions and real recovered dependencies. Zero-total cases observe the original BREAK7 after the counter store. A scoped adapter supplies EE HI/LO values for the original DIV at 001051B0 because generic p-code otherwise stops before the explicit native trap; ordinary divisions still execute. The CPU rule is supported by [PCSX2's DIV implementation](https://github.com/PCSX2/pcsx2/blob/master/pcsx2/R5900OpcodeImpl.cpp). Exception delivery through a live kernel is not claimed.

The DDS comparison resolves the complete chain-builder span 00117B08 to 0011D3B0, including allocator/initializer callee constraints. Both fade commands have two masked complete-span candidates, so their directional identities remain unresolved. The fade state helpers and overlay have no complete-span match under this comparison; shared behavioral fingerprints are recorded as leads, without claiming DDS runtime equivalence.

Current evidence: `analysis/screen-fade-validation.json`, `analysis/screen-fade-abi.json`, `analysis/screen-fade-matches.json` and `analysis/screen-fade-transfer.json`. Compiled comparison and saved interface checks remain distinct from a matching executable or actual PS2 gameplay.
