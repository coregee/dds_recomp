# Native camera selection, scene accessors and projection restoration

Command 18 at 001E76D0 is `evtCommand_CAM_SEL`. The complete Unity body at 181F3F870 preserves the same negative-ID follow-camera path, nonnegative projection restoration and type 4 scene lookup, nonzero camera store and unconditional return 1. The earlier CALL_EVENT lead was contradicted; the HD CALL_EVENT body starts a managed sequence and is unrelated to this native call pattern.

Nine complete native bodies are reconstructed in `src/event_camera.c`. The current suite passes 1,504 original-instruction comparisons: 1,408 cases for newly recovered bodies and 96 connected programs through the existing VM. It covers 728 recognized body bytes and reaches 131 of 133 main instruction addresses. The two remaining generic process-queue dispatch branches are proved unreachable: the index starts at 0, increments once per queue and exits at 3, so dispatch only receives 0, 1, 2. The fixture generator verifies the original initialization, increments, loop bound and dispatch branches before declaring this proof.

Negative camera IDs select the global follow camera; nonnegative IDs restore projection first and then look up a type 4 object. A missing object leaves the current camera unchanged. The scene setter returns the previous sign-extended handle while storing the new low32 bits, even though the command ignores that return. The event-search wrapper returns its actual tail-called scene-search result; its previous generated void prototype was incorrect.

Projection restoration checks the actual process name `fldProcSequence`, a zero field-state gate, event bit AF0, absence of script `elvstart_label`, and equality of the current/follow camera. All gates and their store/no-store outcomes are checked independently. Eight backed camera-table indexes and finite exact angle/scale combinations pass the original MUL.S then DIV.S sequence before the actual FOV setter. The suite includes 81 actual projection-restoration cases and 384 interpreter indirect calls. A scoped CPU value model covers only the reviewed COP1 sites 0012FCA0/0012FCB4; FCSR effects and physical timing are outside that model. The float setter's host adapter preserves raw f12 bits, including signed zero and NaN payloads, and calls the compiled float-facing C body.

Process-name search uses signed LB values for its checksum, then compares bytes in reverse including the terminating NUL. It searches heads 54E850,54E868,54E85C in that order, following next+3C and matching checksum+18. Empty names, high-byte names, hash collisions, misses and matches in each queue are generated. HD uses managed name storage, bounds/null checks and unsigned bytes for its checksum; its layout and high-byte behavior are not substituted into PS2 source.

All nine Unity roles are reviewed. HD camera/control getters use managed objects, while the native follow-control getter returns static 2FC360 and the follow handle is at+78. HD projection restoration calls CROT; the PS2 body explicitly multiplies the table angle by its scale at 54C3B8 and divides by 180. The native FOV setter is a raw SWC1 to 2F59BC.
